# macOS 轻量驻留与菜单栏状态面板

## 目标与实现

- macOS 使用原生菜单栏图标，不创建额外 Vue 面板或 WebView。
- 普通「仅隐藏」保留原逻辑；「轻量驻留」在 IPC 回复后销毁 `main` WebviewWindow，随后将 macOS `ActivationPolicy` 设为 `Accessory`，同时从 Dock 移除应用图标，仅保留原生菜单栏图标。`ExitRequested` 由轻量模式标志阻止退出；后台 `AppState`、Global MCP、隧道与会话持续存活。
- 「恢复主窗口」按 Tauri 配置重新构造 WebviewWindow，重新设为 `ActivationPolicy::Regular`（恢复 Dock 图标），再显示窗口、还原几何并聚焦；不重新创建 AppState，也不主动重启 MCP。
- 系统菜单提供：应用版本、MCP 状态、工作区数、活跃会话数、主进程和界面内存估算、WebView 进程数、恢复窗口、轻量驻留、刷新与完全退出。
- Rust 每 15 秒刷新状态，用户点击菜单栏图标也触发刷新；轻量驻留没有前端轮询。
- 在可见窗口选择菜单栏「轻量驻留」会先通过 `compact-requested` 事件进入 Vue 现有未保存修改检查。Windows 仍保留原托盘左键恢复的语义。

## 内存统计说明

macOS 的 `proc_pid_rusage` 读取主进程 `phys_footprint` / `resident_size`，再加上确认为当前应用子进程、或其责任 PID 指向当前应用的 WebKit helper。不能仅比较两进程的继承责任 PID，否则可能把其他应用的 WebKit 算进来。显示为**估算**，不是整机物理内存的精确独占量。

**「主界面已卸载」与「WebKit 辅助进程数归零」是不同条件**。卸载后，菜单通过 Tauri 窗口注册表确认 `main` WebView 已销毁；macOS WebKit 的 XPC 网络/GPU/内容辅助进程可能被系统延迟回收，短时间仍可能显示数量和内存。不能主动强杀 WebKit XPC（可能被其他进程复用）。菜单应明确标记为「可能滞留」，而非声称它们都是活动界面。无需额外依赖或请求系统管理员权限。

## 验收项目

1. 打开 3+ 个工作区，记录内存；进入轻量驻留后，确认主窗口消失、界面进程数量/内存逐渐下降，菜单栏图标保持可用。
2. 同时通过现有 MCP 客户端调用 `server_info` 和 `workspace_list`，确认服务、会话、连接不断开。
3. 菜单点击「恢复主窗口」，确认页面可以重新访问、窗口尺寸与位置保留，且不重复启动服务。
4. 从主窗口关闭按钮和应用菜单栏进入轻量模式，未保存表单受到保护；「仅隐藏」保留旧行为。
5. 菜单栏「完全退出」确实结束进程；Windows 托盘左键仍直接显示主窗口。
6. macOS 轻量驻留时 Dock 图标消失、菜单栏图标仍可操作；恢复时 Dock 图标重新显示；在 150ms 延迟销毁窗口内立即点「恢复」不会让 Dock 状态反转。

## 验证边界

编译和自动化契约测试不能代替在实际安装版 macOS 上测量进入/退出轻量驻留前后的内存曲线或测试系统睡眠唤醒，需真机验收。
