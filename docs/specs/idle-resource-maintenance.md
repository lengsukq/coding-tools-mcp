# MCP 空闲资源自动回收

## 发现的缺口

- 原有 MCP Session 的 24 小时 TTL 只在被访问时惰性触发回收。
- Computer Use capability 的 10 分钟 TTL 也只在相关调用时回收。
- 已完成的命令驻留内存中的保留输出缓存没有自动回收，原始输出已经有独立的磁盘 TTL。
- MCP 协议端当前使用 Axum HTTP JSON，没有常驻 SSE 推送连接池，不应随意终止活跃 HTTP 请求。

## 实现策略

- Tauri 桌面进程每 5 分钟进行一次周期清理，不依赖 WebView 或 MCP listener 是否处于轻量模式。
- MCP Session 超过 30 分钟没有活动才清理；进行中的 RPC 持有引用计数式租约，确保长请求不被误删。请求结束刷新最后活动时间。
- Computer Use capability 保持原 10 分钟 TTL，周期清理到期条目及所属会话已删除的条目，不改变安全边界。
- 已完成的命令只有在完成时间超过 30 分钟、最后访问也超过 30 分钟，且当前没有其他引用时，才释放内存对象；运行中命令永不因闲置被杀掉。
- 命令完整输出在原有磁盘缓存目录按已有 3 天 / 512MB 上限管理，自动清理不直接删除原始输出；MCP、FRP 与 Cloudflare 持续运行。
- 菜单栏标识累计“定时回收”的会话数量，日志按轮记录释放的会话、能力令牌和完成命令数量。

## 验收

检查过期会话、长请求保护、Computer Use 能力令牌过期、已完成命令回收、运行中命令保留，并验证轻量驻留不会中断维护任务。
